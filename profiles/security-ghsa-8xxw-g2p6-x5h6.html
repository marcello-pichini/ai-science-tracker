HTTP/2 compressed headers can amplify server memory usage with built-in TLS

Yopass · AI involvement attributed to Anthropic's OSS Scanner

Finding and attribution

Yopass leaves MaxHeaderBytes unset on its application and metrics listeners. An unauthenticated client can repeat HPACK-compressed cookie fields across concurrent HTTP/2 requests; Go expands the headers into per-request strings retained while bodies are pending. Requires an HTTP/2-enabled built-in TLS listener or a proxy that forwards large decoded headers. Historical releases without HTTP/2 support are not exposed to this variant; this does not reveal secret content or bypass secret authorization.

What to update · Yopass

Affected versions not confirmed in this summary.

Remediation note: Yopass 16.0.0 fixes the issue (commit 23b56941c7597690e17907f90d4c0fe6d90049a). Affected-version scope: Built-in TLS versions 4.0.1 through 15.1.0, subject to runtime and listener configuration; fixed in 16.0.0 by setting MaxHeaderBytes to 16 KiB on both listeners. Patch availability does not establish downstream deployment.
