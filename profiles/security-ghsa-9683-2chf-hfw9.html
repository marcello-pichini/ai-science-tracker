BlueZ LE Audio BASE parser stack buffer overflow

BlueZ · AI involvement attributed to Claude

Finding and attribution

In the LE Audio BASE parser, an attacker-controlled Audio_Channel_Allocation LTV length is passed to memcpy into a four-byte stack local in bap_sink_match_allocation(); a second copy exists in bap_sink_get_allocation(). The advisory describes an over-the-air periodic advertisement path within BLE range, without pairing, connection, or user interaction, when the BAP sink and experimental kernel ISO socket path are enabled. With _FORTIFY_SOURCE >= 2 the daemon aborts; with _FORTIFY_SOURCE=0 the source describes a 195-byte-or-greater attacker-controlled write into root-running bluetoothd. The advisory lists no patched release and only proposes checking that the LTV length equals sizeof(uint32_t). Its affected scope is tied to a 2026-04-14 historical master snapshot, not a current exact boundary.
