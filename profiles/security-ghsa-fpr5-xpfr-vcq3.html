AV1 long UVLC values can bypass libheif coded-size limits

libheif · AI involvement attributed to Anthropic OSS Scanner (model not specified for this finding)

Finding and attribution

The AV1 scanner used a UVLC reader that rejected values after 20 leading zero bits even though the format allows 31 for the field, then ignored the failure. This let libaom allocate an oversized frame after the security check. The advisory reports up to about 3.5 GB peak memory on a crafted small AVIF.

Product: libheif. AI system: Anthropic OSS Scanner (model not specified for this finding). Team / organization: Anthropic and libheif maintainers.

CVE identifiers: Not established in the cited evidence.

AI and human contribution (source account): The item-level libheif advisory explicitly attributes discovery to Anthropic's OSS Scanner as ANT-2026-ESNQYZED. The release notes independently state that all listed security issues were found by the scanner. The Anthropic program sources establish model-based scanning, but no per-case model is identified.

Human involvement is only described where the source account establishes it; unknown involvement does not mean none. Vendor confirmation of a flaw does not confirm every claim about AI contribution.

Remediation status: fix documented. The AV1 UVLC reader now follows the specification and rejects incomplete sequence headers; fixed in libheif 1.23.7. The confirmed affected configuration uses libaom for AV1 decoding; dav1d and FFmpeg independently enforce limits. The libheif v1.23.7 security release is dated 2026-10-26; deployed patch status is not checked.
