Quadratic stsc lookup can cause denial of service during HEIF open

libheif · AI involvement attributed to Anthropic OSS Scanner (model not specified for this finding)

Finding and attribution

Opening a file with a moov box used a linear search of stsc entries for every chunk, yielding quadratic work and seconds-to-minutes CPU use on files with many chunks. This issue was also independently reported as GHSA-xf84-wgwm-8vhx; the advisory explicitly says Anthropic OSS Scanner independently discovered the same issue.

Product: libheif. AI system: Anthropic OSS Scanner (model not specified for this finding). Team / organization: Anthropic and libheif maintainers.

CVE identifiers: Not established in the cited evidence.

AI and human contribution (source account): The item-level libheif advisory explicitly attributes discovery to Anthropic's OSS Scanner as ANT-2026-ZNJZAJWY. The release notes independently state that all listed security issues were found by the scanner. The Anthropic program sources establish model-based scanning, but no per-case model is identified.

Human involvement is only described where the source account establishes it; unknown involvement does not mean none. Vendor confirmation of a flaw does not confirm every claim about AI contribution.

Discovery context: The primary advisory establishes a publicly disclosed security finding and direct Anthropic OSS Scanner attribution. No CVE had been assigned in the libheif release notes at the checked time; the distinct GHSA is used. No exploitation or zero-day status is asserted.

Remediation status: fix documented. The lookup is now a binary search and malformed decreasing first_chunk values are rejected; fixed in libheif 1.23.7. The advisory also discloses OpenAI Codex assistance with the human reporter’s review and drafting; Anthropic discovery attribution is separately explicit. The libheif v1.23.7 security release is dated 2026-10-26; deployed patch status is not checked.
