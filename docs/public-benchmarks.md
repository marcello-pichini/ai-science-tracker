## What changed and what must travel with reuse

We selected numerical results, renamed fields and labeled evaluation slices. Scores retain their original numeric scales and precision in JSON; the table rounds display values to four decimal places. Original inference labels and available source methodology are retained. We did not add model-name joins, recalculate accuracy, estimate new confidence bounds, or infer missing scores or evaluation dates. The source order is retained.

When redistributing a component, retain its attribution, source/revision links, license, disclaimers and change notices. CC BY components require appropriate credit, a license link and disclosure of modifications. The **CharXiv adapted numerical file remains CC BY-SA 4.0**: retain the same obligations and license adaptations under CC BY-SA 4.0, including applicable database adaptations. This obligation applies to that component; it does not relicense unrelated code or datasets merely collected beside it. Do not impose extra downstream restrictions. MIT components retain their original copyright and full permission/disclaimer notice. Apache components retain their license and applicable notices; our extraction/field changes are explicitly stated in every file. No source root NOTICE file was present in the reviewed repository listings. Preserve any additional notices introduced by future source revisions.

Questions, expected answers, paper charts, external copyrighted corpora, prompts, attack payloads, conversations, private data, contact details and trajectories are **not redistributed** in these components. The source licenses do not imply source-author endorsement. Linked model licenses describe those models, not the numerical dataset license.

## Interpretation limits

- GPQA configurations can use different reasoning settings and budgets. Source stderr is not a confidence interval. We import Epoch's own-run CSV only: its external SciCode/LiveBench/etc. imports retain external rights and are excluded.
- Arena measures preferences. Rating points are not percentages, and different categories or publication dates are not directly comparable. Source-provided rating bounds and vote counts remain in details.
- τ² text results are separated by domain, version, retrieval and simulator where reported. A slice is a viewing aid, not proof of identical settings. Other settings and source methodology notes may differ or apply only to one domain; consult the exact submission. Submission, evaluation and model-release dates are not interchangeable.
- ChemBench is a two-report **legacy selection**, not the current separately hosted ChemBench-Results feed. The source labels do not identify exact releases. BixBench zero-shot baselines are not agentic bioinformatics results.
- MMLU-Pro, CharXiv, RULER and AgentDojo contain historical models and protocols. CharXiv's archive was last modified in September 2024; we do not import newer website results. Reference controls such as Human or Random are not independent model releases.
- RULER claimed length is not effective length. Its original source notes attribute Jamba results to the contributing report, FILM to its paper (YaRN beyond 32K and no one-shot CWE example), and Qwen/EXAONE results to their respective papers. Original notes remain linked per row. This is the selected original README table, not RULER v2.
- AgentDojo attack success is **lower is better**; utility is **higher is better**. Attack and defense settings differ.
- SWE-bench Pro's selected source calls its scores **initial runs subject to change**. This collection is distinct from SWE-bench Verified (whose existing component is CC BY-NC 4.0) and from separate Scale commercial/private result feeds.

## METR interpretation and permission

METR directly confirmed on 18 November 2026 that its public data may be recreated/published under CC BY 4.0. This numerical component follows that grant with METR attribution, the paper citation, source URLs, original values, full license text and modification notices. Private correspondence, contact details and mail headers are not redistributed. This permission does not grant access to private tasks or relicense the analysis code or third-party materials.

The selected exports provide **human-expert baseline minutes** at **50% or 80% predicted success**. They do not measure AI wall-clock runtime, continuous autonomous operation, all occupational tasks or job replacement. Date columns are source model-release dates, not evaluation/publication dates. Missing intervals remain unreported; the displayed 95% bootstrap confidence bounds are supplied by METR and are not confidence levels for a model ranking.

Version **1.1** and version **1.0** use different task suites and remain separate evaluation slices. The v1.1 export includes three older baselines explicitly labeled v1.0; their full records match the v1.0 export and are retained once there, rather than mislabeled as v1.1 reruns. This produces 46 v1.1 observations and 66 v1.0 observations, each horizon counted separately. Scaffolds and task-suite revision hashes stay attached to each record; there is no inferred join to Epoch labels or new trend fit.

METR says measurements **above 16 hours are unreliable with this task suite**; such central estimates carry an explicit warning. METR also marks its source page **no longer actively updated**, with a page notice dated **8 September 2026**. The daily job checks the two approved public exports for changes, validates supported suite/schema, public-data permission scope, legal notices and numerical intervals, and retains the last accepted component if a check fails. It does not promise new METR evaluations. A changed endpoint, evaluation suite or conflicting inherited baseline requires review.

## Reproduction and maintenance

The existing **Daily refresh** workflow checks all eleven selections every day at **04:30 UTC** (05:30 Zurich in winter, 06:30 in summer), alongside Epoch and SWE-bench Verified. `scripts/refresh_public_benchmarks.py` accepts source updates only within the stated selections and supported formats. It checks numerical-dataset license metadata, exact approved legal texts, new repository NOTICE files, complete pagination, stable HF revisions, numerical validity and selected protocol assumptions. It preserves attribution, source pins, hashes and component-specific dates. Unchanged numerical content does not advance a snapshot date or create a benchmark change. If a source is inaccessible or a rights/format/protocol check fails, its last accepted component is retained; other valid updates may proceed. A visible Actions warning, job summary and 30-day per-source report artifact record held sources. A changed license or unsupported format needs explicit review; the job does not guess permission or silently relicense data. Historical/preliminary scope still applies: checking an old archive daily does not make its evaluations recent. New external leaderboards and broader selections are not automatically admitted.

`scripts/public-benchmark-inputs.json` pins the reviewed raw inputs, Git commits/HF revisions, SHA-256 hashes and notices. Raw files stay in private `work/`; they must not be committed. Rebuild against the retained input cache:

```sh
python3 scripts/import_public_benchmarks.py --inputs work/metric-enrichment
```

For available remote inputs, `--download` retrieves missing pinned files and refuses hash mismatches. Arena uses the complete 11,177-row frozen text/latest Parquet file before selecting the 421 overall observations; the HF revision is checked unchanged across retrieval. This avoids repeatedly requesting the paginated dataset-viewer API. Install the build-time reader with `python3 -m pip install -r scripts/requirements-benchmarks.txt`; Apache Arrow is a build dependency only, not website JavaScript. **The Epoch ZIP URL is mutable**: if it changes, the old source cache or the appropriate archived upstream export is needed to reproduce the old snapshot. The importer stops rather than silently replace it. A new date/revision is a new reviewed snapshot, not a refresh of the old date.

The importer writes `data/benchmarks/*.json`; do not edit those outputs manually. License notices in `docs/benchmark-licenses/` are exact copies of the reviewed upstream texts. The browser validates the directory and all its numerical components together with progress/SWE against the shared exact-byte component manifest, then displays one selected collection at a time. Selecting another source does not fetch an independent cache or join it to Epoch names. Failure clears all attempted metric values and offers Retry and attributed downloads. Detailed observations use a native disclosure; source/slice controls and context remain immediately accessible. No external libraries or runtime requests to third parties are used.
